# 로봇 CLI AI 작업 지시서 — MR 경로 주행 최소 변경

## 1. 목표와 역할 분담

대상 저장소는 `Ksyear/PuppyPI_Cpp_ROS2`입니다. 검토한 기준 커밋은 `3d29ef16cebd12bfe3edeeed6c6b7d064a4e8a80`이며, 실제 작업 브랜치가 다르면 현재 코드를 먼저 확인하세요. 기존 사용자 변경을 되돌리지 마세요.

**로봇의 자체 LiDAR 장애물 정지·재출발 판단을 제거하고, 장애물 필터·경로 취소·우회는 MR이 담당하게 만드세요.** 로봇은 MR이 보낸 경유점을 추종하고 실행 상태를 보고합니다. 짧은 경로가 첫 상태 조회 전에 완료되어도 MR이 이번 실행의 완료인지 식별할 수 있어야 합니다.

이번 작업은 새로운 장애물 정지 알고리즘을 만드는 작업이 아닙니다. 잡음 때문에 정지하고 해제를 기다리는 조건을 줄이는 최소 변경입니다. 계획 제시로 끝내지 말고 코드 변경과 모터 없는 검증을 수행하세요.

## 2. 수정할 위치

기본 경로: `ros2_ws/src/puppy_vr_bridge/puppy_vr_bridge/`

| 파일 | 필요한 변경 |
| --- | --- |
| `path_follower.py` | 원시 LiDAR 장애물 정지·clear-hold 제거, 실행 식별자 보관·상태 출력 |
| `v2_server.py` | 수락한 경로 요청의 UUID와 sequence를 실제 경로 적용 콜백에 전달 |
| `receiver_node.py` | 실제 `set_path()` 호출에 요청 식별자 전달 |
| `/api/path`를 제공하는 코드 | 필요할 때만 수정: 새 식별자 두 항목을 응답에서 누락하지 않도록 전달 |

참고 패치: [ros2_path_reliability.patch](../patches/ros2_path_reliability.patch). 기준 버전용이므로 현재 소스와 비교하고 적용하세요. MR 저장소의 Unity 코드와 스마트폰 앱은 이번 로봇 작업 범위에 포함하지 않습니다.

## 3. 제거할 정지·재출발 동작

현재 `PathFollower.update()`의 다음 연결을 제거하세요.

1. `obstacle_count(scan_pts, cfg) >= min_obstacle_points`만으로 정지하는 분기.
2. 이 판정으로 `state = "blocked"`를 설정하고 출력을 0으로 만드는 동작.
3. LiDAR 점이 사라진 뒤 `_clear_since`와 `clear_hold_sec`를 기다리는 재출발 동작.
4. 위 LiDAR 판정 때문에 경로 취소·비상정지·수동 리셋을 요구하는 동작이 다른 위치에도 있는지 확인하고 같은 범위에서 제거.

기존 ROS 파라미터·상태 스키마와의 호환성을 위해 사용하지 않는 설정 키나 `blocked` 문자열 정의를 남겨도 됩니다. 단, 실제 경로 주행에서 이 키가 별도 장애물 정지·해제 대기를 발생시키면 안 됩니다. 경유점 도착 판정, 회전·직진 전환, 주행 속도와 방향 보정은 유지하세요.

**다음 대체 조건을 로봇에 새로 넣지 마세요.**

- 근접 거리나 원시 점 수만으로 만드는 새로운 장애물 정지.
- 장애물이 사라진 뒤 8cm 더 먼 공간을 측정해야 하는 조건.
- 빈 공간을 3회 관측하거나 별도의 안정화 시간을 채워야 하는 조건.
- 지도 전체·전방 전체가 비어 있어야 출발하는 조건.
- 새로운 confidence, 유효 점 수, 관측 누적 기준으로 만드는 출발 잠금.

## 4. 반드시 유지할 정지 보호

아래는 장애물 분류와 별개이므로 유지하세요.

- 사용자가 누르는 비상정지와 기존 해제 절차.
- UDP watchdog, lease 만료, 조종 소유권 검사와 소유권 상실 시 정지.
- neutral ACK, 수동 조종 우선권, 중재기·엔진의 기존 이동 허가.
- 경로 실행 중 위치·스캔 메시지가 실제로 끊겼을 때의 기존 timeout 정지.
- 기존 위치 급변·지도 원점 초기화 감지에 따른 경로 취소.
- MR의 `path_cancel`과 lifecycle 정지 요청 처리.
- 기존 속도 상한과 정지 출력 우선 처리.

기존 timeout 값을 임의로 늘리거나 줄이지 마세요. 스캔 만료 검사는 최초 회전 출력 전에도 적용하세요. 잡음·데이터 부족을 이유로 새로운 **비상정지 래치**나 수동 RESET 조건을 추가하지 마세요. 일반 경로 중단, 통신 timeout 정지, 비상정지를 같은 상태로 합치지 마세요. 경로 취소 통신까지 실패하는 상황의 기존 보호는 유지합니다.

## 5. 실제 경로 실행 식별자

기존 UDP v2 경로 요청 형식은 유지합니다. 새 패킷 필드를 요구하지 말고, 이미 있는 `client_id`와 `sequence`를 사용하세요.

실제 적용된 경로 상태에 아래 두 필드를 추가하세요.

- `request_client_id`: 해당 경로를 요청한 소유자의 UUID.
- `request_sequence`: 해당 `path` 패킷의 sequence 정수.

필수 동작:

1. UDP ACK 전송은 수신 확인일 뿐입니다. **실제 경로 적용 콜백에서 `set_path()`가 실행될 때** 식별자를 기록하세요.
2. ACK만 보낸 시점에 이전 경로의 상태를 새 식별자로 바꾸면 안 됩니다.
3. `rotate`, `drive`, `done`, `cancelled` 상태에서도 같은 경로 식별자를 유지하세요.
4. 다음 `path`가 실제 적용될 때만 새 식별자로 바꾸세요. 중립 heartbeat의 sequence로 덮어쓰면 안 됩니다.
5. `path_cancel`은 취소된 경로의 식별자를 유지합니다. 취소 패킷의 sequence를 실행 식별자로 덮어쓰지 마세요.
6. 다른 소유자·중복·역순·거부된 요청은 현재 실행 식별자를 바꾸면 안 됩니다.
7. 식별자 없는 이전 호출이나 시작 전 상태는 두 필드 모두 `null`로 반환하세요. 한쪽만 채우지 마세요.
8. `/api/path`가 ROS 상태를 캐시한다면 두 필드가 HTTP 응답까지 그대로 전달되는지 확인하세요.

완료 응답 예시입니다. 다른 기존 필드와 `age_s`의 의미는 유지하세요.

```json
{
  "media": "puppypi-media/1",
  "age_s": 0.0,
  "session_state": "idle",
  "emergency_stop": false,
  "path": {
    "state": "done",
    "waiting": null,
    "reason": null,
    "request_client_id": "a92e1842-7ef1-4d1f-bc14-2a04dcd0da87",
    "request_sequence": 142,
    "points": [[0.0, 0.0], [0.12, 0.0]],
    "index": 2,
    "count": 2,
    "elapsed_s": 0.16
  }
}
```

`done`은 `index == count`여야 합니다. sequence는 문자열·실수 대신 기존 프로토콜의 정수 범위를 유지하세요. 기존 두 인자 경로 콜백을 쓰는 호출자가 있다면 호환성을 유지하거나 모든 호출부를 함께 갱신하세요.

## 6. 모터 없는 필수 회귀 검증

실제 production follower·프로토콜·서버 모듈을 사용하고 출력 콜백은 가짜 출력으로 대체하세요. ROS 노드 실행, 모터 명령, 실제 로봇 이동 없이 먼저 확인합니다.

| 시나리오 | 기대 결과 |
| --- | --- |
| 0.8초마다 0.1초간 전방 잡음 2점 | 로봇 내부 `blocked`, clear-hold, 경로 취소, 비상정지 없이 전달된 경로 추종 |
| 연속된 원시 장애물 점 | 로봇은 별도 LiDAR 정지를 만들지 않음. MR의 `path_cancel`을 받으면 정지 |
| 정상 경로 후 두 번째 경로 | 같은 소유권 세션에서 새 sequence로 정상 실행 |
| 12cm 목표, 도착 반경 10cm | 첫 HTTP 조회 전에 완료되어도 이번 요청의 ID를 가진 `done` 반환 |
| 동일 좌표 경로 재요청, ACK 후 콜백 지연 | 콜백 전에는 이전 ID, 실제 적용 후에는 새 ID. 이전 완료를 새 실행으로 표시하지 않음 |
| 경로 ACK 지연·유실, 중립 heartbeat 정상 | 경로 자동 재전송 없이 상태의 실제 실행 ID로 구분 가능 |
| 중립 heartbeat·취소·거부된 경로 요청 | 실행 ID 갱신 규칙이 위 5절과 일치 |
| 위치·스캔 메시지 중단 | 기존 timeout에 따라 전진·회전 출력 0. 새 임의 timeout이나 RESET 조건 없음 |
| 비상정지·소유권 상실·watchdog·중재기 차단 | 기존 정지 보호가 유지됨 |

MR 저장소에서 제공하는 검증 도구를 사용할 경우:

```sh
python3 tools/validate_ros2_path_identity.py \
  --robot-src /path/to/PuppyPI_Cpp_ROS2/ros2_ws/src/puppy_vr_bridge/puppy_vr_bridge
```

로봇 단독 원시 장애물 테스트에서는 실제 물체를 향해 주행시키지 마세요. 해당 판정을 MR로 옮기는 변경이므로 가짜 시계·가짜 출력으로 검증합니다. 실물 통합 시에는 MR의 장애물 확정 → 경로 취소 → 정지 확인 → 우회 순서가 작동하는지 별도로 확인하세요.

## 7. 결과 보고와 적용

변경한 파일, 제거한 분기, 유지한 정지 보호, 추가한 상태 필드와 실제 검증 결과를 보고하세요. 테스트 수만 제시하지 말고 반복 잡음·짧은 완료·이전 동일 경로 상태가 각각 어떻게 처리됐는지 적으세요. 실물 테스트를 하지 않았다면 명시하세요.

패치를 적용할 때는 로봇 저장소 루트에서 먼저 확인합니다.

```sh
git apply --check /path/to/PuppyPi_MR_Controller/patches/ros2_path_reliability.patch
git apply /path/to/PuppyPi_MR_Controller/patches/ros2_path_reliability.patch
```

현재 브랜치와 충돌하면 관련 변경을 보존하며 맞춰 적용하세요. 빌드·서비스 이름은 저장소와 현재 장치 설정에서 확인하세요. 확인하지 않은 서비스 재시작 명령을 추측하지 마세요. 소스 수정만으로 실행 중인 로봇 서비스가 교체되었다고 보고하지 마세요.

로봇 적용 후에는 실행 ID를 읽는 MR 빌드와 함께 확인해야 합니다. 로봇 저장소 수정만으로 Quest에 설치된 APK가 바뀌지는 않습니다.
