# VR–PuppyPi 조종 및 통신 규격 협의안

작성일: 2026-09-28  
상태: 구현 전 협의안 — 아래 수치와 동작은 양측 확인 후 확정

## 1. 목표와 현재 상태

VR 콕핏에서 손잡이를 잡고 기울여 PuppyPi의 전후진과 회전을 조종하려고 합니다. 조금 기울이면 천천히, 많이 기울이면 빠르게 움직이는 조종감을 목표로 합니다.

현재 데모는 UDP로 `X:12.3,Z:-5.0` 형태의 관절 각도를 전송합니다. 아래 JSON 규격은 이를 대체할 **새로운 제안**이며, 아직 구현된 규격이 아닙니다. 기존 라즈베리파이 수신 데모는 이 JSON을 바로 처리하지 못하므로 송수신 양쪽을 함께 변경해야 합니다.

## 2. 양측 역할

| 구분 | 담당할 동작 |
|---|---|
| VR | 잡기·놓기 감지, 사용할 그립 선택, 관절 축과 방향 보정, 중립 구간과 감도 곡선 적용, 최종 이동 명령 송신 |
| PuppyPi | 명령 검증, 조작 강도를 실제 보행·회전 속도로 변환, 속도 상한과 가감속 제한 적용, 통신 단절 시 정지 |

VR에서는 그립마다 입력을 해석하는 전략을 두고, 현재 선택된 전략의 출력만 **하나의 공통 송신기**에서 전송할 예정입니다. 로봇은 그립 종류나 Unity 관절 각도를 알 필요 없이 동일한 이동 명령을 처리하면 됩니다.

## 3. 그립 조작과 이동 강도

손잡기를 잡으면 해당 그립 전략을 선택하고, 현재 조종 중인 손잡기를 놓으면 중립 전략으로 전환합니다. 손을 놓은 뒤 가상 관절이 복귀하는 움직임은 로봇 명령에 반영하지 않습니다. 손 추적 상실과 앱 일시정지·포커스 상실도 중립 전환 대상으로 처리할 예정입니다.

다음은 최대 기울기 40도를 가정한 감도 설계 예시입니다. 실제 그립 역할과 축 배정, 구간별 출력값은 VR 조작 테스트 후 확정합니다.

| 기울기 크기 | 의도하는 조종감 |
|---|---|
| 0~5도 | 중립 구간: 손떨림을 무시하고 0 출력 |
| 5~15도 | 낮은 속도에서 미세 조종 |
| 15~30도 | 기울기에 따라 점진적으로 속도 증가 |
| 30~40도 | 합의한 최대 속도까지 증가 |

이 구간은 고정된 3단 속도 명령을 뜻하지 않습니다. 가능하면 구간 사이의 출력도 연속적으로 이어지게 만들고 싶습니다. PuppyPi가 연속 속도 제어를 지원하지 않는다면, 지원하는 보행 단계와 전환 방식에 맞춰 조정하겠습니다.

## 4. 전송 방식 제안

| 항목 | 제안 |
|---|---|
| 전송 방식 | UDP, UTF-8 JSON |
| 메시지 단위 | UDP 데이터그램 하나에 JSON 객체 하나 |
| 목적지 | PuppyPi의 IP 주소, UDP 포트 `5005` — 네트워크 환경에 맞춰 확정 |
| 전송 주기 | 20Hz, 약 50ms마다 전송 |
| 중립 상태 | 앱 송신 루프가 동작하는 동안 정지 상태도 주기적으로 전송 |
| 정지 전환 | 주기 전송을 기다리지 않고 중립 명령을 즉시 전송 |

과거 이동 명령은 재전송하지 않고, 매번 현재 상태를 보냅니다. 앱이 중단되거나 네트워크가 끊기면 정지 패킷 자체가 도착하지 않을 수 있으므로 수신 측 시간 제한도 함께 필요합니다.

## 5. 명령 데이터 규격

```json
{
  "version": 1,
  "session_id": "d8b27f10-09a8-4c21-b649-1e7058d46b72",
  "seq": 123,
  "control_active": true,
  "forward": 0.6,
  "turn": -0.3
}
```

아래 필드는 모두 필수로 제안합니다.

| 필드 | 자료형·범위 | 의미 |
|---|---|---|
| `version` | 정수, 현재 `1` | 프로토콜 버전 |
| `session_id` | UUID 문자열 | VR 앱 실행마다 새로 생성하는 세션 식별자. 같은 실행 중에는 유지 |
| `seq` | 0 이상의 정수 | 세션 내에서 0부터 시작해 메시지마다 1씩 증가. 중립 메시지도 포함 |
| `control_active` | 불리언 | 유효한 조종 입력이 있는 상태인지 표시 |
| `forward` | 유한한 숫자, `-1.0~1.0` | 양수 전진, 음수 후진, 0 전후진 없음 |
| `turn` | 유한한 숫자, `-1.0~1.0` | 양수 좌회전, 음수 우회전, 0 회전 없음 |

방향은 **로봇이 바라보는 전방 기준**입니다. 후진 중에도 `turn`의 부호 의미는 유지하는 것으로 제안합니다. 숫자는 문자열이 아닌 JSON 숫자로 보내며, 소수점은 `.`을 사용합니다. `NaN`과 무한대는 허용하지 않습니다.

`forward: 0.6`은 전진 속도 상한의 60%에 해당하는 목표값입니다. 실제 속도 단위, 전진·후진 각각의 상한, 최대 회전 속도는 로봇 측에서 정하고 공유 부탁드립니다. 두 축을 동시에 입력했을 때의 속도 제한도 로봇 측에서 안정적인 범위로 적용해야 합니다.

`seq`는 구현 간 숫자 호환성을 위해 최대 `9007199254740991`까지 사용하고 같은 세션에서 되돌리거나 순환시키지 않습니다.

## 6. 정지와 중립의 의미

손잡기를 놓거나 조종 입력을 상실했을 때 보내는 예시입니다.

```json
{
  "version": 1,
  "session_id": "d8b27f10-09a8-4c21-b649-1e7058d46b72",
  "seq": 124,
  "control_active": false,
  "forward": 0.0,
  "turn": 0.0
}
```

| 상태 | 해석 |
|---|---|
| `control_active: true`, 두 축 0 | 손잡기를 잡고 중립에 있는 상태. 이동 목표는 0 |
| `control_active: true`, 축 값 존재 | 해당 전후진·회전 목표를 적용 |
| `control_active: false` | 축 값과 관계없이 이동 목표를 0으로 처리. VR은 두 축도 0으로 전송 |

여기서 정지는 **보행·회전의 정지 요청**입니다. 모터 전원 차단이나 하드웨어 비상정지를 뜻하지 않습니다. 정지할 때 자세를 유지하는 방법과 감속 시간은 PuppyPi의 제어 방식에 맞춰 확정해야 합니다.

앱 복귀나 추적 복구 후에는 기존 이동 명령을 자동 재개하지 않고, 중립에서 다시 잡아야 조종을 시작하도록 제안합니다. 동시에 여러 그립을 잡는 경우의 선택 정책은 VR에서 처리하며, 현재 선택되지 않은 그립의 놓기 이벤트는 현재 조종을 해제하지 않습니다.

## 7. 수신 측 처리 규칙 제안

1. 수신기 시작 시 이동 목표는 0으로 둡니다.
2. JSON 형식, 필수 필드, 자료형, 버전, 숫자 범위를 검사합니다. 잘못된 패킷은 거부하며 유효 수신 시간을 갱신하지 않습니다. 부가 필드는 향후 확장을 위해 무시할 수 있습니다.
3. 현재 세션에서 마지막으로 처리한 `seq`보다 큰 명령만 처리합니다. 중복되거나 뒤늦게 도착한 패킷은 무시하고 유효 수신 시간도 갱신하지 않습니다.
4. 인정한 명령이 `control_active: false`이면 즉시 정지 처리를 시작합니다. 활성 명령이면 두 축을 로봇의 목표 속도로 변환합니다.
5. 마지막으로 인정한 명령 이후 **500ms** 동안 새 유효 명령이 없으면 정지합니다. 500ms는 초기 시험값이며 네트워크 지연과 정지 응답을 보고 조정합니다. 시간 측정에는 수신기 자체의 단조 증가 시계를 사용합니다.
6. 타임아웃 뒤에는 활성 이동 명령만으로 자동 재개하지 않습니다. 새 중립 명령을 먼저 인정한 뒤 이후의 활성 명령으로 재개하도록 제안합니다.

### 세션 변경

앱 재실행으로 `seq`가 다시 0부터 시작하는 상황을 구분하기 위해 `session_id`를 사용합니다.

- 제어 송신원은 한 대로 제한하며 허용할 VR 송신 주소를 합의합니다. `session_id` 자체는 인증 정보가 아닙니다.
- 수신기 시작 시에는 유효한 중립 명령을 먼저 받아 세션을 등록합니다.
- 다른 세션으로 바꾸는 것은 기존 세션이 중립 상태이거나 타임아웃으로 정지된 상태에서만 허용합니다. 새 세션의 첫 명령도 중립이어야 합니다.
- 교체된 세션 ID는 수신기 실행 중 다시 채택하지 않아, 늦게 도착한 이전 세션 패킷으로 조종이 되돌아가지 않게 합니다.

실기기 연결 절차에 맞춰 더 단순한 명시적 연결·해제 방식을 사용하는 것도 협의 가능합니다. 송신원 변경과 재연결 동작은 양쪽 구현 전에 함께 확정하고 싶습니다.

## 8. 선택 사항: 로봇 상태 회신

1차 이동 시험에서는 명령 수신부터 맞추고, 이후 아래와 같은 회신을 추가하면 VR 화면에서 실제 연결 상태를 표시할 수 있습니다. 회신 포트·주기·필드 상세는 별도 협의 항목입니다.

```json
{
  "version": 1,
  "session_id": "d8b27f10-09a8-4c21-b649-1e7058d46b72",
  "last_seq": 124,
  "state": "idle"
}
```

상태 후보는 `idle`(중립), `active`(조종 활성), `timeout`(명령 시간 초과), `fault`(로봇 오류)입니다. 수신 확인은 실제 이동 완료나 측정 속도 확인과는 구분합니다.

## 9. 로봇 담당자 확인 요청

- 전후진 속도와 회전 속도를 연속적으로 지정할 수 있나요? 정해진 보행 단계만 지원한다면 단계별 값과 전환 조건을 알려주세요.
- 전진·후진·제자리 회전 및 전후진과 회전의 동시 입력을 지원하나요?
- 양수 전진 / 양수 좌회전이라는 부호 규칙으로 맞출 수 있나요?
- 전진·후진 최대 속도, 최대 회전 속도, 적절한 가감속 제한은 어느 정도인가요?
- 20Hz 입력을 받는 것이 적절한가요? 내부 제어 주기에 맞춰 가장 최근 목표값을 유지·적용할 수 있나요?
- 중립 명령 및 500ms 명령 시간 초과에 대한 정지 처리가 가능한가요? 보행 정지 시 자세 유지와 정지 지연은 어떻게 되나요?
- 재연결 시 중립 확인, 세션 교체, 이전 패킷 무시 규칙을 위 제안대로 적용할 수 있나요?
- 사용할 네트워크, PuppyPi IP, 허용할 VR 송신 주소와 포트를 어떻게 정하면 될까요?
- 이후 상태 회신 기능도 제공할 수 있나요?

## 10. 함께 확인할 시험 항목

| 시험 | 기대 결과 |
|---|---|
| 앱 시작, 손잡기를 잡지 않음 | 중립 명령만 전송되고 로봇은 정지 |
| 그립을 조금씩 기울임 | 강도에 따라 목표 속도가 연속적으로 변함 |
| 방향 부호 시험 | 전진·후진·좌회전·우회전이 합의한 방향과 일치 |
| 미선택 그립 조작 | 최종 송신값에 영향 없음 |
| 현재 그립을 놓음 | 즉시 중립 명령이 전송되고 관절 복귀는 명령에 반영되지 않음 |
| 손 추적 상실·앱 일시정지 | 중립 전송을 시도하며, 전송이 끊기면 수신 측 시간 제한으로 정지 |
| 네트워크 단절 | 마지막 유효 명령 이후 합의한 제한 시간에 정지 처리 시작 |
| 오류 패킷이 계속 도착 | 유효 명령 시간 제한이 갱신되지 않아 정지 |
| 오래된 번호·중복 패킷 도착 | 이전 동작으로 되돌아가지 않고 시간 제한도 갱신하지 않음 |
| 통신 복구·앱 재실행 | 중립 확인 후 새 조작으로 재개, 이전 명령 자동 재개 없음 |

실제 이동 시험은 낮은 속도 상한으로 시작하고, 로봇 응답을 확인하면서 감도 곡선과 속도 상한을 함께 조정하고 싶습니다.
