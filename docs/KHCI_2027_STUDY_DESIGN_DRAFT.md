# KHCI 2027 PuppyPi 장애물 통과 주행 비교 연구 초안

수정일: 2026-11-10. 사용자가 개편 중인 연구 방향을 반영한 문서다. 세 조종 방식의 비교를 기준으로 하며, 코스·완료 판정·난이도·로그 확장은 아래와 같이 설계할 후보이다. 실제 장치 성능이나 새 실험 통합의 검증 완료를 의미하지 않는다.

## 1. 현재 연구 방향

사용자는 물체·표식 인식 과제보다 **장애물 사이를 통과해 목표 지점까지 이동하는 주행 과제**를 중심으로 연구를 개편하려고 한다.

| 조종 방식 | 사용자 입력 | 로봇 이동 방식 |
| --- | --- | --- |
| 스마트폰 터치 조이스틱 | 전후·회전을 계속 입력 | 수동 연속 제어 |
| MR BallGrip | 손으로 가상 손잡이를 조작 | 수동 연속 제어 |
| MR 지도 경로 그리기 | 라이다 기반 지도에 손으로 선을 그려 경로 지정 | 지정 경로 추종 |

기존 QR 판독·프레이밍 성공 조건은 새 주행 실험의 주성공 기준으로 사용하지 않는다. 기존 약 1m·30도는 점검 표식 시나리오에서 정한 파일럿 시작안이므로 장애물 코스의 거리로 자동 확정하지 않는다. 이미 구현된 판독 기능을 제거하라는 뜻은 아니다.

연구의 중심은 **세 조종 방식의 장애물 통과 수행, 계획·수정·개입 비용, 사용자 작업부하 비교**이다. 스마트폰과 MR 사이에는 장치·관찰 방식이, 수동 조종과 경로 지정 사이에는 지도 정보·자동화 수준이 함께 달라진다. 시스템 전체 비교로 설명하고 성능 차이를 손 입력 하나의 효과로 해석하지 않는다.

## 2. 시나리오와 과제 구성 후보

참가자 안내문 초안:

> 지정된 출발 구역에서 시작해 장애물 사이의 통로를 통과하고 목표 구역에 로봇을 정지시키세요. 가능한 한 신속하게 수행하되 장애물과의 접촉을 피하세요.

- 같은 출발·목표 구역과 장애물 배치를 세 방식에 사용한다.
- 첫 실험은 고정된 장애물 배치로 구성하는 것을 제안한다. 움직이는 장애물이나 자동 우회 능력을 검증하는 과제로 확장하지 않는다.
- 코스 후보는 넓은 통로의 단순 회전 코스와 방향 전환이 여러 번 필요한 굴곡 코스다. 이는 코스 유형 후보이며, 통로 폭·회전 수를 동시에 바꾸고 특정 요인 하나의 효과라고 주장하지 않는다.
- 난이도 하나의 효과를 연구하려면 같은 코스에서 통로 폭 등 한 요인만 바꾸는 설계를 검토한다.
- 실제 로봇 몸체·회전 여유와 지도 경로 검증의 clearance 제한을 모두 만족하는 코스를 먼저 확인한다. 경로 방식만 구조적으로 통과할 수 없는 코스를 비교 과제로 사용하지 않는다.
- 이동거리·통로 폭·장애물 개수·제한시간은 파일럿에서 실제 보행 속도와 시행 길이를 확인한 뒤 고정한다.
- 실제 로봇을 직접 관찰하는 기존 환경을 기준으로 하되, 세 조건에 제공하는 지도·카메라·상태 정보와 사용자 위치·이동 허용 범위를 명시한다.

## 3. 현재 경로 기능의 범위

[MR Map Path Editor](MR_MAP_PATH_EDITOR.md)에 따르면 지도는 로봇의 occupancy grid와 pose를 사용하며, 원본 선·보정된 waypoint 경로를 검토하고 RUN으로 실행한다. 경로의 거부·취소·수동 조종 개입을 구별할 수 있다.

문서상 unknown/occupied 영역과 부족한 clearance는 경로를 거부하고, 실행 중 전방 장애물에서는 정지·대기한다. 자동 우회 경로 계획은 이 편집기의 기능으로 구현되어 있지 않다. 따라서 이번 비교는 사용자가 그린 경로의 추종을 포함하는 것이며, 자율 우회 알고리즘의 우수성을 평가하는 것은 아니다. 실제 보행과 장애물 통과 가능성은 별도 장치 확인이 필요하다.

라이다 지도는 실시간 데이터로 갱신되는 표현이지만 누적 occupancy grid 갱신이 카메라 영상보다 느릴 수 있다. 원본 시각·세션·좌표계와 갱신 간격을 기록하고 현재 지도 상태의 유효성을 확인한다.

## 4. 연구 질문 후보

| 질문 | 내용 | 주요 자료 |
| --- | --- | --- |
| RQ1 | 세 조종 방식의 장애물 코스 목표 도달 시간과 성공률은 어떻게 다른가? | 계획·입력을 포함한 전체 시간, 성공·시간 초과·중단 |
| RQ2 | 코스 요구에 따라 계획·경로 수정·수동 개입과 조작 연속성의 차이는 어떻게 달라지는가? | 그리기·수정 시간, 정지·재개, 경로 취소·재지정·개입 |
| RQ3 | 각 방식의 작업부하·지각된 사용성과 선호 이유는 어떻게 다른가? | NASA-TLX, SUS, 인터뷰와 로그 연결 |

핵심 주장은 사용자 주행 수행이다. 실제 환경과 가상 지도·로봇 위치를 동기화하고 지도 위의 경로가 실제 이동으로 이어지는 구조는 디지털 트윈을 설명할 근거이지만, 표현 대상·갱신 주기·충실도와 검증 범위를 정의해야 한다. 지도 갱신이나 경로 추종 자체의 정밀도를 사용자 수행 효과와 혼동하지 않는다.

## 5. 공통 성공·실패 판정의 재설계

세 방식 모두 같은 목표 구역과 판정 규칙을 사용해야 한다. 경로 방식의 `path completed`만 성공으로 삼고 수동 방식은 참가자의 완료 버튼으로 판정하는 혼합 기준을 피한다.

앱·로봇 로그만 사용하는 기본 후보:

1. 로봇 추정 pose가 공통 좌표계의 목표 구역에 도달한다.
2. 최신의 서로 다른 원본 측정에서 지정 유지 조건을 만족한다.
3. 필요한 중립·정지 조건을 만족한다. 중립 명령을 실제 물리적 정지의 실측으로 부르지 않는다.

이 방식의 결과는 **로봇 위치추정 좌표계에서 판정한 목표 도달**이다. 물리적 실제 위치 오차를 검증한 것은 아니다. 지도 reset·pose 점프·stale data·중복 샘플·좌표계 변경이 성공 유지로 누적되지 않도록 한다. 적절한 원본 pose를 확보할 수 없으면 완료 판정 방법을 다시 정하고 한 방식만 다른 수단으로 판정하지 않는다.

시간 초과·사용자 중단·기기/위치추정 문제를 구분한다. 조건에 내재한 추적 실패·경로 거부 등을 임의로 제거하지 않는다. 실험자 실수·데이터 유실의 재시행 규칙은 본실험 전에 정한다.

## 6. 지표와 측정 범위

| 지표 | 정의와 전제 |
| --- | --- |
| 전체 완료 시간 | 공통 신호 이후 입력 획득·경로 작성·수정·실행 지시·이동·필요한 재조정을 모두 포함 |
| 성공·시간 초과·중단 | 같은 목표 판정과 제한시간 사용. 성공한 시행만의 평균으로 우열을 정하지 않음 |
| 추정 주행거리 | 로봇 원본 pose로 계산한 거리. 데이터 갱신·좌표 점프와 누락을 함께 점검 |
| 정지·재개·개입 비용 | 사용자 정지와 시스템 이유의 차단을 구별. 개입 이후의 시간도 전체 시간에 포함 |
| 경로 작성·수정·거부·취소 | 경로 방식의 과정 지표. 다른 방식의 터치·잡기 횟수와 단순 동등 비교하지 않음 |
| 센서 기준 근접·장애물 정지 | 같은 센서·판정 정책과 계측 연결이 있을 때 산출. 전방 감지·정지를 실제 충돌 횟수로 바꾸어 부르지 않음 |
| 사용자 작업부하·사용성 | 조건별 NASA-TLX·SUS, 관측 결과와 인터뷰 연결 |

**실제 물리적 충돌 횟수**는 신뢰 가능한 접촉 감지나 별도 관찰 기록이 있을 때만 보고한다. 라이다 최소 거리나 제어기의 obstacle stop 이벤트만으로 충돌을 단정하지 않는다. 같은 센서 정책을 세 조건에 적용했는지도 확인한다.

**경로 이탈·추종 오차**는 기준 경로가 무엇인지 먼저 정한다. 손으로 그린 선에 대한 추종 오차는 경로 방식의 부가 지표이며, 기준 선을 주지 않은 수동 조종과 그대로 비교할 공통 지표가 아니다. 공통 통로 중심선을 기준으로 쓰려면 그 의미·제공 정보·좌표계·유효성을 별도로 정의한다.

## 7. 실험·로그 변경 요구

- 세 번째 방식에는 별도 `interface_id`가 필요하다. `mr_map_path`는 문서상의 제안 ID이며 실제 계약과 맞춰 확정한다. 기존 `smartphone_touch`, `mr_ballgrip`을 재사용해 경로 시행을 섞지 않는다.
- 제시 순서는 시스템 ID와 별도 기록한다. 세 방식의 가능한 여섯 순서에 균형 배정하는 것을 검토하고 배정 방법과 seed를 남긴다.
- 공통 manifest: 코스/배치 버전, 출발·목표, 지도·좌표계·세션, 정보 제공 범위, 속도·회전 제한, 난이도, 코드·설정 버전.
- 공통 사건: 신호 제시, 최초 유효 입력, 목표 진입·이탈·성공, 정지·재개·중단·시간 초과, 제어 차단과 원인.
- 경로 사건: 그리기 시작/종료, 원본 선·실행 waypoint, 보정·수정·재작성, RUN, 수락·실제 실행 시작, 거부·진행·대기·취소·완료, 수동 개입.
- 수동과 경로 방식 모두 실제 명령의 로봇 수신·수락과 원본 pose·센서의 시각/품질을 기록한다. pose 샘플을 앱 프레임마다 복사하여 측정률이 높아진 것처럼 처리하지 않는다.
- 기기 간 시계 정렬·로그 누락·수락과 실제 실행의 구별을 유지한다.

기존 QR 중심 판정·로그·분석기의 재사용 범위와 변경할 성공 판정 계약을 검토해야 한다. 이 문서는 새 주행 실험에 대한 구현 완료 보고가 아니다. 코드·API·테스트는 이번 연구 문서 수정에서 변경하지 않는다.

## 8. 다음에 정할 항목

1. 실제 통과 가능한 고정 장애물 배치와 코스 길이.
2. 목표 구역과 공통 도달 판정에 사용할 원본 pose의 제공·품질.
3. 센서 기준 근접·정지 지표와 실제 접촉 관찰을 포함할지 여부.
4. 지도 경로 방식에서 수동 개입을 허용할 범위와 해당 시행의 결과 처리.
5. 코스 유형/난이도, 제한시간, 연습·반복 수·참가자 수.
6. 세 조건에 제공하는 지도·실제 로봇·카메라·상태 정보.
